# Modulith 交付与验证

领域蓝图不是一次画图活动。交付必须让后续开发者和 Agent 能判断能力放哪里、依赖谁、怎样证明没有跑偏。

## 输出层次

使用 `assets/backend-domain-blueprint-template.md` 组织分析底稿，再按 `document-blueprint` 沉淀长期真相源：

- 领域长期边界、公开能力、依赖和规约进入对应 `spec-*`。
- 结构、能力归属、依赖方向和行为证据进入对应 `validation-*`。
- 本次拆分、合并、迁移顺序、兼容和回滚进入 `plan-*`。
- 精确接口和事件字段进入 `api-*`。
- 表、索引、回填、双写和切流进入 `sql-*`。
- 部署、观测、运行架构、外部执行面和回滚进入 `ops-*`。

不要把全部领域放进一篇巨型 Spec。每个具有独立语言、规则和所有权的限界上下文应有清晰真相源，公共总览只负责路由和全局关系。

## 验证矩阵

| 验证层 | 证明什么 | 典型证据 |
|---|---|---|
| 业务语义 | 统一语言、规则和公开能力归属正确 | Spec、评审结论、领域目录 |
| 结构边界 | 模块无环、内部包不可跨域访问、允许依赖正确 | simple-modulith / Spring Modulith 结构测试 |
| 数据所有权 | 每张主表、流水、缓存和对象索引只有一个写入所有者 | Dao 扫描、SQL、数据血缘、代码评审 |
| 契约边界 | Req/Resp、Entity、历史 JSON 和供应商对象未跨域泄漏 | API / Event 契约测试、源码检查 |
| 行为正确 | 拆分前后核心规则、状态、幂等、事务和失败恢复一致 | 单元测试、H2/集成测试、回归用例 |
| 业务接入 | 新公开面已被真实入口调用，不是只创建空壳结构 | 调用链、入口测试、日志或运行态回证 |
| 迁移完成 | 旧路径、双写、临时适配和放宽依赖按计划清理 | `rg`、删除清单、迁移门禁 |
| 运行健康 | 目标版本已部署且关键业务、日志和数据正常 | 健康检查、版本、日志、只读数据证据 |

## 结构测试

最低要求：

- 业务模块无循环依赖。
- 其他模块只能访问领域公开面或明确命名接口。
- `allowedDependencies` 与蓝图一致，禁止依赖能够被测试发现。
- Action / Controller 不访问领域内部包。
- 一个领域不访问另一个领域的 Dao、Entity 或私有表。
- 领域公开接口只由能力拥有方实现。
- OPEN 技术模块不承载业务规则或充当跨域中转站。

结构测试通过不等于领域设计正确。还必须用业务语言、数据所有权、事务/失败边界和真实业务接入证明边界有业务依据。

## 当前事实与目标设计

交付结论固定分成四段：

1. **当前已落地**：代码、数据或运行环境已经证明的事实。
2. **目标蓝图**：领域边界、协作契约和 Modulith 结构的目标状态。
3. **迁移步骤**：从当前到目标的可验证增量。
4. **阻塞与待确认**：尚未验证、外部依赖失败或需要业务裁决的事项。

不使用“基本完成”“大体支持”掩盖关键阻塞。HTTP 成功、类已创建、包已拆分或测试能编译，都不能单独证明业务能力已落地。

## 交付前检查

- [ ] 已读取目标项目 `AGENTS.md`、README、相关 Spec / Validation / API / SQL / Ops。
- [ ] 已盘点实际代码和数据所有权，没有只基于旧文档重画。
- [ ] 每个候选领域都有拆分或合并证据，不依赖“复用性”单点判断。
- [ ] 业务领域 DAG、上下文协作和运行架构职责分离。
- [ ] 图中每个节点和边都能在目录 / 协作表中找到解释。
- [ ] 公开能力、能力实现、数据所有权、事务与失败责任一致。
- [ ] 业务基础域没有被固定 `foundation` 包替代，技术节点没有伪装成领域。
- [ ] 当前事实、目标设计、迁移步骤和未决问题明确分开。
- [ ] Modulith 映射包含当前与目标 package、允许依赖和渐进迁移顺序。
- [ ] 验证覆盖结构、数据、契约、行为、真实接入和运行回证。
- [ ] 已执行文档链接检查和目标项目可用的最小结构 / 回归测试。

## 失败判定

出现任一情况，领域蓝图不能判定完成：

- 只给图，没有术语、所有权、公开能力和依赖语义。
- 业务 DAG 混入 Worker、MQ、存储、供应商、Controller 或 Dao。
- 领域边界直接来自现有 package，未核对业务语言和数据生命周期。
- 同一业务能力或主数据存在两个未解释的拥有方。
- 目标设计覆盖了当前事实，无法判断哪些已经落地。
- 新模块只有骨架，真实业务入口仍走旧路径，却宣称迁移完成。
- 结构测试通过，但跨域仍共享表、Entity、历史 payload 或内部 Service。
- 关键循环依赖、兼容层或外部阻塞没有进入迁移计划。
