# 知识库关联

## 目标

把知识库作为项目工作的上下文和结果沉淀层：开始工作时先找已有经验，结束工作时再判断是否需要形成可复用记录。库的位置和边界以 [references/vault-map.md](references/vault-map.md) 为准；每个库怎么写，以库里自己的规则文件为准。

## 触发判断

遇到以下情况时考虑关联知识库：

- 当前任务涉及之前做过的方案、故障、配置、迁移或决策。
- 任务产生了以后维护、排障或复用时有价值的结论。
- 用户要求整理、归档、记录或更新知识库。
- 用户说“记到学习库”“我想学 X”“整理成学习笔记”“这个还没搞懂，先记着”“读一下这篇文章记下来”。

普通一次性问答、临时命令解释和没有长期价值的简单修改，不创建笔记。

## 库的选择

1. 公司项目按当前路径和内容进对应的工作库：完美像素用 `wmxs`，共享基础服务用 `sfs`，信息流广告投放用 `feed`。一件事的内容不写进另一个库。
2. 当前路径在 `~/work/codes/wmxs` 下时，按 `~/work/doc/wmxs/projects/INDEX.md` 判断业务域和项目知识库位置；其中 `ads/feed-pilot`、`ads/ad-creative` 的知识库在 `~/work/doc/feed/projects/`。
3. 学习笔记写入 `learn`，在哪个项目目录下都一样。只在用户说要记、要学时写，普通问答不主动写入。
4. 个人事务（家庭网络、NAS、装修、个人设备）没有对应的库。服务器和机器的变更记在 homelab 仓库；其余需要沉淀时先问用户放哪里。
5. 归属不明确时先只读盘点相关路径和项目名；涉及个人与公司边界时暂停写入，向用户确认。
6. 库之间不合并，不用软链接互相穿透，不跨库复制原文。公司内部信息不写进 `learn`。

## 工作流程

### 开始任务：检索

1. 从当前项目名称、用户目标、服务名和错误信息提取 2～6 个检索词。
2. 只在选定的库里定向搜索 Markdown、属性和索引页；优先用 `rg` 或 Obsidian 搜索，不读取整个库。
3. 查看命中的少量笔记，提取与当前任务直接相关的事实、约束、历史决策和链接。
4. 在进度说明里简要说明已关联的知识；没有命中就继续工作，不为了搜索扩大范围。

### 任务过程中：引用

- 把相关笔记当作背景事实使用，保留笔记路径或标题，避免凭记忆重复推断。
- 笔记与当前事实冲突时，以当前可验证的事实为准，并标记需要更新的旧笔记。

### 任务结束：沉淀

满足以下任一条件才写入或更新笔记：

- 得出了以后会复用的方案、决策、配置或排障结论。
- 用户明确要求整理、记录、归档或更新知识库。

沉淀时遵循：

1. 优先更新已有的主笔记，不为同一主题创建多个“最终版”。
2. 按所在库自己的规则写：`wmxs`、`feed`、`learn` 看根目录的 `README.md`；`sfs` 看 `CONVENTIONS.md`，写完跑 `python3 _scripts/sfs.py check`。
3. 笔记写结论、依据、操作结果、风险和下一步；不复制大段原始日志或整份外部文档。
4. 记录日期、来源路径和相关项目；不写入密码、Token、私钥或其他敏感凭据。

### 写学习笔记（learn）

读的人是用户，写的是代理。结构、属性和写作规则在 `~/work/doc/learn/README.md`，动笔前先读它。

1. 读 `README.md` 和要用的模板（`_templates/`）。
2. 先找已有笔记：`rg -l <关键词> ~/work/doc/learn/topics ~/work/doc/learn/sources`。同一个概念已经有笔记就更新它，不另写一篇。
3. 动笔前把事实核实清楚。能在本机跑的就跑一遍，把命令和实际输出写进例子；引用文档的先读原文再写，附链接；没核实的标“未核实”。
4. 写笔记，并挂到所属主题的地图（`topics/<主题>/<主题>.md`）。没有合适的主题就新建目录和地图。
5. 用户只是说“还没搞懂，先记着”的，在 `待弄懂的问题.md` 加一行，不硬写成笔记。写笔记时自己留下的疑问也记在那里。
6. 检查并提交：

   ```bash
   obsidian vault=learn unresolved   # 应输出 No unresolved links found.；Obsidian 没开就跳过
   cd ~/work/doc/learn && git add -A && git commit -m "<中文说明>" && git push
   ```

主题地图里的勾选框是用户的学习进度，由用户自己勾。

## 安全与副作用边界

- 默认先读后写。不自动移动或删除现有笔记，不批量重命名，不批量安装插件或开启同步。
- 不自行改变各个库的存放和同步方式：不新增远端，不复制到 NAS 或其他位置。
- Obsidian 的应用缓存、数据库、日志和整个 `~/Library/Application Support/obsidian` 不作为知识库内容处理。
- 四个库的阅读样式（主题、样式片段、插件设置）保持一致，要改就一起改。
- 大视频、原始照片和安装包留在文件目录，笔记里用路径或链接关联。

## 输出方式

关联知识库后，在回复中说明：

- 用了哪个库。
- 找到了哪些与当前任务相关的已有知识。
- 是否新增或更新了笔记，以及笔记标题。

没有进行关联时，只在确有必要时说明原因，不展开无关的细节。
